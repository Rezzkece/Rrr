FINDING #1: cPanel and Webmail Exposed via Redirect
Severity: HIGH | CVSS: 7.5
URL: https://smpn1kretek.sch.id/cpanel -> https://imola.id.domainesia.com:2083/
URL: https://smpn1kretek.sch.id/webmail -> https://imola.id.domainesia.com:2096/

DESCRIPTION:
The school domain has redirects to cPanel and Webmail hosted on a shared
DomaiNesia server (IMOLA.ID). The login pages are accessible, though they
require authentication.

PROOF:
======

# 1. cPanel redirect confirmed
$ curl -s -L https://smpn1kretek.sch.id/cpanel -o /dev/null -w "%{url_effective}"
https://imola.id.domainesia.com:2083/

# 2. Webmail redirect confirmed
$ curl -s -L https://smpn1kretek.sch.id/webmail -o /dev/null -w "%{url_effective}"
https://imola.id.domainesia.com:2096/

# 3. cPanel login page accessible
$ curl -s -I https://imola.id.domainesia.com:2083/
HTTP/2 200
Content-Type: text/html; charset=UTF-8

# 4. Login-protected (credentials rejected)
$ curl -s -X POST https://imola.id.domainesia.com:2083/login/ \
  -d "user=root&pass=root" -o /dev/null -w "%{http_code}"
401

# 5. WHM not directly exposed
$ curl -s -I https://imola.id.domainesia.com:2087/
000 (Not reachable)

KNOWN RISKS:
- cPanel is on a shared hosting environment (DomaiNesia/IMOLA)
- Side-channel attacks possible on shared infrastructure
- Default credential attacks against cPanel
- Webmail credentials could be phished via the redirect
- Port 2083/2096 exposed on shared server

REMEDIATION:
- Restrict cPanel/Webmail access to VPN or internal network only
- Remove the redirects from the school domain
- Implement IP allowlisting on cPanel
- Change default credentials immediately
- Enable two-factor authentication on cPanel

FINDING #2: No Security Headers
Severity: MEDIUM | CVSS: 5.3
URL: https://smpn1kretek.sch.id/

DESCRIPTION:
The main site lacks essential security headers that protect against common
web vulnerabilities.

PROOF:
======

# Security headers present:
- Server: DomaiNesia
- Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
- X-Dynamic-Cache: MISS

# Security headers MISSING:
- X-Frame-Options (clickjacking protection)
- X-Content-Type-Options (MIME sniffing protection)
- Content-Security-Policy (XSS protection)
- Referrer-Policy (referrer leakage)
- Permissions-Policy (browser feature control)

# Comparison with previous target (smpn2kretek.sch.id):
# smpn2kretek had HSTS + X-Frame-Options + X-Content-Type-Options + CSP + Referrer-Policy + Permissions-Policy
# smpn1kretek has ONLY HSTS

RISK:
- Clickjacking attacks possible (no X-Frame-Options)
- MIME sniffing attacks possible (no X-Content-Type-Options)
- XSS attacks possible (no CSP)
- Referrer data leakage (no Referrer-Policy)
- Browser features uncontrolled (no Permissions-Policy)

REMEDIATION:
- Add X-Frame-Options: SAMEORIGIN
- Add X-Content-Type-Options: nosniff
- Add Content-Security-Policy header
- Add Referrer-Policy: strict-origin-when-cross-origin
- Add Permissions-Policy header
